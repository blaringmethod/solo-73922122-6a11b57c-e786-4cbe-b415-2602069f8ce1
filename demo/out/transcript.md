# 复扫页数核对 · 联机演示记录

服务地址：`http://127.0.0.1:8030`

- 健康检查 `GET /healthz` → HTTP 200

## 第 1 步：导入批次清单与汇总单

- `POST /import` → HTTP 200，落点 `http://127.0.0.1:8030/?submission=1`

清单：
```
B01 r2
B02 r2
B03 r1
B04 r1
```
汇总单：
```
S1 150
B01 r2
B02 r2

S2 90
B03 r1
B04 r1
```

## 第 2 步：勾选全部四个批次核对
- `GET /?check=1&batch=B01&batch=B02&batch=B03&batch=B04` → HTTP 200，结果状态 `ok`，报数 240 页
- 期望：S1+S2 唯一有效组合，150+90=240。

## 第 3 步：更新 B01 现行修订号为 r3（旧汇总单失效）

- `POST /revision` → HTTP 200，落点 `http://127.0.0.1:8030/`
- 不采用理由：B01 单上修订 r2 ≠ 现行 r3
- 再次核对四个批次 → 结果状态 `none`
- 期望：S1 含 B01 r2 已不采用；B01 无可用单覆盖，因此无法出数（S2 仍可用但只覆盖 B03/B04）。

## 第 4 步：换版后重新导入吻合的汇总单，并制造分歧

- `POST /import`（清单 r3 + 新单 T1/T2）→ HTTP 200
- 核对 B01+B02 → 状态 `ok`，报数 150 页（T1=150）

再导入一张与 T1 覆盖相同、合计不同的 T3＝170，制造汇总分歧：
- `POST /import` → HTTP 200
- 核对 B01+B02 → 状态 `conflict`
- 分歧：T1 → 合计 150 页
- 分歧：T3 → 合计 170 页
- 期望：T1（150）与 T3（170）是两组不同的有效组合，页面应分别列出单号与合计，而不报单一数字。

## 结论

- 自动判定：通过（分歧场景状态 = `conflict`）
- 分歧两组：T1；T3
- 原始响应保存在 `demo/out/`。
